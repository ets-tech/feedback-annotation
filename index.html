Feedback Annotation

Point at anything on a page, say what should change, and send every note from every page as one report. Built on Agentation, added with one script tag.

Try it on this page

  1. Click the round Agentation button in the bottom-right corner to start annotating.
  2. Click anything on this page, such as a card below, type what should change and press Add.
  3. A Send 1 Feedback tab appears on the right edge. Open it to share the report by WhatsApp, Telegram or Email, copy it, or download it.

Add it to an app

Paste one tag into the page's HTML. It must be type="module".

<script type="module" src="https://cdn.jsdelivr.net/gh/ets-tech/feedback-annotation@1/feedback-annotation.min.js?app=MyApp"></script>

@1 picks up every 1.x fix automatically and never a breaking 2.0. Drop .min from the file name for the readable version.

For dev and staging only. Don't ship the tag to production.

Post to server

Set post_url and the drawer gets a Post to server button. It sends one POST with a JSON array: every note on every page, plus the notes deleted since the last successful post. Notes stay in the browser afterwards, so posting again re-sends them.

<script type="module" src="https://cdn.jsdelivr.net/gh/ets-tech/feedback-annotation@1/feedback-annotation.min.js?app=MyApp&post_url=https%3A%2F%2Fapi.example.com%2Ffeedback&post_token=abc123"></script>

  • hash is the SHA-256 of app + origin + deviceId + agentation.id. It stays the same when a note is edited, so upsert by hash. deviceId is a random id kept per browser, so two testers' notes never share a hash.
  • deleted: true items are notes the tester deleted. The server decides what to do with them; a hash it has never seen can be ignored.
  • Clear all first posts every note as deleted and clears nothing unless the server answers 2xx. If some notes were never posted, or were edited since, the dialog says so and offers Post to server.
  • Any 2xx is success. A failure shows "Failed (status)" and logs the status and response body to the console.

Fields

Headers: Content-Type: application/json, plus Authorization: Bearer <token> when post_token is set. Optional Agentation fields are left out when empty, never sent as null.

FieldMeaning
hashSHA-256 hex of app + origin + deviceId + agentation.id; the upsert key
deletedfalse for a live note
app, deviceId, originThe app parameter, a random id kept per browser, and the site's origin
sessionId, publicIpThe session ID at send time (changing it re-sends the same hash), and the tester's public IP or null
urlFull address of the page the note was made on, with query and fragment
path, query, fragmentIts parts: /orders, ?date=2026-10-01 (or empty), #/orders/42 on hash-routed apps (or empty)
userAgent, viewport, devicePixelRatio, sentAtBrowser, width×height, pixel ratio and ISO time, all at send time

agentation.id, .timestampAgentation's creation time in ms (string and number). id is unique only per browser, hence hash.
commentThe tester's feedback
element, elementPath, fullPathReadable element name, short CSS path, full DOM path
x, y, boundingBoxMarker at % from left and px from top; element box {x, y, width, height}

isMultiSelect, elementBoundingBoxes, isFixed, frameMulti-select and its boxes; position-fixed element; iframe path for notes inside an iframe

A deleted note carries only hash, deleted: true, app, deviceId, sessionId, deletedAt and agentation: { id }.

The server must answer the CORS preflight (Access-Control-Allow-Origin for the site and Access-Control-Allow-Headers: Authorization, Content-Type; no cookies are sent) and check the Origin header against the sites it expects.

The token sits in the page's HTML, so anyone who can open the page can read it. Make it write-only and good for this endpoint alone.

How it works

  • Notes stay in the tester's own browser. Nothing is sent anywhere until they share, copy, download or post the report. The one outside call is a public IP lookup to api.ipify.org.
  • The first note asks for a session ID, such as a Jira ticket or GitHub issue. Left blank it becomes MyApp- plus 8 random characters. It heads the report, names the download, and can be changed from Session in the drawer.
  • The report starts "I added 3 feedbacks on host. Fix each one, then verify it in the running app:", ready to paste into an AI agent.
  • The report covers every page of the app, grouped by page address (path, query and # part), in Agentation's detailed "forensic" format.
  • Clear all removes every note on every page, after a confirmation.
  • The tab follows Agentation's light and dark theme.
  • Loads React 19.3.0 and Agentation 3.1.2 from esm.sh; this script itself comes from jsDelivr.
